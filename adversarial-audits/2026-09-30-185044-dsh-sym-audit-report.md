# dsh-sym — 对抗性审计报告

## 1. 边界、方法与威胁假设

**审计范围**：`lib/host-v6.js`、`lib/client.js`、`test/`（本轮新引入）、
`package.json`、`adversarial-audits/` 的产出规范。

**不覆盖**：DSH 官方包内部；运行期压测；GitHub 配置。

**方法**：按 `attack-playbook.md` 的域逐项遍历，重点四个域——
**测试**（因为本轮刚引入测试脚手架）、**产品逻辑**、**并发**、**资源**。
命令与输出均已复核：

```bash
grep -c "^test(" test/host.test.mjs                 # 断言规模
node --test test/host.test.mjs                      # 实际通过情况
grep -n "throws\|rejects" test/host.test.mjs        # 失败路径覆盖
grep -n "globalThis" test/helpers/load-client.mjs   # 全局污染
rg -n "ctx.slots.inject" lib/client.js              # 注册点
git diff --stat HEAD -- lib/                        # 生产代码影响面
```

**威胁假设**：维护者（人或 AI）在**没有接口文档**的情况下修改本项目；
测试会被当作"已验证"的证据使用。

**未覆盖部分**：**未做动态分析**（无并发压力、无长时间运行），
因此资源类结论均为 **静态推断**，下文已标注。

## 2. 发现清单

**缺陷优先。** 严重度 `S0`–`S3`；证据等级 `已验证` / `高置信推断` / `未验证假设`。

| ID | 严重度 | 证据等级 | 缺陷 | 触发条件 | 错误行为 | 为何重要 | 位置 |
|---|---|---|---|---|---|---|---|
| **AUD-TEST-001** | **S1** | 已验证 | **同一模块的接口契约不可发现**——本次审计过程中，同一个 AI 在**同一会话内对 `lib/host-v6.js` 的接口连续误判 6 次** | 任何未读过实现的人（或新会话的 AI）基于名字推断用法 | 写出的代码/测试**静默错误**：不报错，只是**行为与预期不符**（如"未知 id 应原样保留"实为"返回新批次"） | 契约靠**读实现**才能得知，而项目**无 .d.ts、无类型、无 API 参考**；6 次误判全部需要一个"预期失败"的测试才能暴露 | `lib/host-v6.js` 导出面；`AGENTS.md` 缺接口章节 |
| **AUD-TEST-002** | **S2** | 已验证 | **测试无失败路径断言**：`test/host.test.mjs` 33 处 `assert`，`throws`/`rejects` **零处** | 非法入参被传入 | 失败路径的行为（是抛错、返回 `null`，还是静默通过）**无人验证** | 反模式"未测主路径/权限路径/**失败路径**"；本项目 `return null` 出现 20 次，全是未测的失败分支 | `test/host.test.mjs` |

| **AUD-LOGIC-001** | **S3** | 已验证 | **有标记但展开失败时仍拷贝整个批次**：`expandQuoteText` 只要发现标记就返回新字符串，于是 `changed` 被置真 | 文本含 `@引用#` 但该 id 已不在索引（>400 条前的回复） | 每次 `pre-step` 都为**无效标记**复制整个消息批次 | 无效输入走最重路径；虽量小，但属"静默吞错"的邻域——**失败仍被当作变化** | `lib/host-v6.js` `expandQuoteText` |
| AUD-DOC-002 | S2 | 已验证 | 项目 `AGENTS.md` 记录了**边界与流程**，但**未记录导出函数的签名** | 新会话接手 | 见 AUD-TEST-001 的根因 | 记忆文件记"不能做什么"却不记"接口长什么样"，正是误判 6 次的直接土壤 | `AGENTS.md` |

## 4. 总评

- **整体判断**：**功能正确性未见缺陷；风险集中在"契约不可见"与"测试深度"**。
  本轮新引入的测试**立刻抓出 6 处误判**——这既证明测试有效，也证明**误判的土壤仍在**。
- **最该先修的三项**：
  1. **AUD-TEST-001（S1）** —— 它是其他所有误判的根因
  2. **AUD-TEST-002（S2）** —— 失败路径完全未测，而代码里 20 个 `return null` 全是失败分支
  3. **AUD-OPS-001（S2，复发）** —— 上轮已报未修，且本项目**已实际发生两次**
- **不建议修但需知晓的**：AUD-LOGIC-001 的拷贝行为是**当时的实现选择**，
  若改为精确判定需谨慎处理 `QUOTE_MARK` 的 `lastIndex` 状态（该正则带 `g` 标志，已有显式重置）。
